# Build Instructions: libpd Python Bindings with MSVC

This guide explains how to build the `libpd` Python bindings (`pylibpd`) on Windows using Microsoft Visual C++ (MSVC) instead of MinGW, without modifying any of the original repository files.

---

## Prerequisites

Before running the build, ensure the following software is installed on your system:

1. **Python**:
   - The native Windows version of Python (installed from [python.org](https://www.python.org)).
   - Ensure it is in your system `PATH`.
2. **Visual Studio or Build Tools**:
   - Install **Visual Studio** or **Build Tools for Visual Studio**.
   - Make sure you select the **Desktop development with C++** workload.
3. **SWIG (Simplified Wrapper and Interface Generator)**:
   - SWIG is required to translate the [pylibpd.i](file:///D:/me/MUSICA/dev/libpd/python/pylibpd.i) interface file into C code.
   - Download the Windows zip package from [swig.org](http://www.swig.org/download.html).
   - Extract the contents (e.g. to `C:\swigwin`) and add that directory to your Windows system `PATH` environment variable.
   - *Note: If using Python 3.14, make sure to download SWIG 4.4.0 or newer.*
4. **Pthreads for Windows**:
   - `libpd` requires a POSIX threads (`pthreads`) implementation.
   - You have `pthreads` installed via vcpkg at:
     - `PTHREADS_INCLUDE_DIR`: `D:/me/dev/vcpkg/packages/pthreads_x64-windows/include`
     - `PTHREADS_LIB`: `D:/me/dev/vcpkg/packages/pthreads_x64-windows/lib/pthreadVC3.lib`

## Step-by-Step Build Instructions

### Step 1: Open the VS Developer Command Prompt
Standard terminal prompts do not have MSVC's compiler environment set up. 
- Open the Windows Start Menu, search for **Developer Command Prompt for VS** (or **Developer PowerShell for VS**), and launch it.

### Step 2: Navigate to the Python Directory
In the developer prompt, change directory to the `python` folder in your project:
```cmd
cd /d D:\me\MUSICA\dev\libpd\python
```

### Step 3: Run CMake to Generate Build Files
Clean any old cached configuration, create the build directory, and configure CMake with your specific paths for `pthreads` and your custom Python 3.12 path:

```cmd
rmdir /s /q build
mkdir build
cd build
cmake .. -G "Visual Studio 17 2022" -A x64 -DPTHREADS_INCLUDE_DIR="D:/me/dev/vcpkg/packages/pthreads_x64-windows/include" -DPTHREADS_LIB="D:/me/dev/vcpkg/packages/pthreads_x64-windows/lib/pthreadVC3.lib" -DPython_ROOT_DIR="C:/Users/giohappy/AppData/Local/Python/pythoncore-3.12-64"
```

> [!NOTE]
> Adjust the generator `-G "Visual Studio 17 2022"` and `-A x64` to match your installed Visual Studio version and target Python architecture.

### Step 4: Build the Extension
Compile the Python module:
```cmd
cmake --build . --config Release
```

Upon successful compilation:
- A post-build command in [CMakeLists.txt](file:///D:/me/MUSICA/dev/libpd/python/CMakeLists.txt) automatically copies:
  1. `_pylibpd.pyd` (compiled C extension)
  2. `pylibpd.py` (python wrapper module generated by SWIG)
- These files are copied back into your main [python/](file:///D:/me/MUSICA/dev/libpd/python) directory.

---

## Running & Verifying

### Run-time DLL Requirement
Since `libpd` is linked against the `pthreads` DLL, Windows needs to be able to locate it when you import the module:
- Copy the `pthreadVC3.dll` (found in your pthreads library directory) into the [python/](file:///D:/me/MUSICA/dev/libpd/python) folder next to `_pylibpd.pyd`, **or** ensure its folder is in your system `PATH`.

### Verification Test
To verify the build is working, run a quick Python test in the [python/](file:///D:/me/MUSICA/dev/libpd/python) directory:
```cmd
cd ..
python -c "import pylibpd; print('pylibpd successfully imported!'); print('Block size:', pylibpd.libpd_blocksize())"
```
If you see the block size printed (usually 64), the build succeeded and is ready for use!
